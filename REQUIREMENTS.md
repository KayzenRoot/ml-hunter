# ML Hunter Requirements

Product requirements are not yet approved. This file currently records only repository/governance requirements that are factual and necessary for safe planning.

## Governance requirements

- **MLH-GOV-001**: Substantial work must be bounded by a stable Work Order.
- **MLH-GOV-002**: Each Work Order must identify scope, acceptance criteria, tests/evidence and STOP CONDITION.
- **MLH-GOV-003**: The checkpoint must identify current governed state and next legal action.
- **MLH-GOV-004**: Evidence must bind to the candidate commit/workflow used for acceptance.
- **MLH-GOV-005**: Exact-head audit is required before accepting substantial PRs.
- **MLH-GOV-006**: Missing evidence cannot be recorded as PASS.
- **MLH-GOV-007**: CRITICAL/HIGH unresolved findings block governed release acceptance.
- **MLH-GOV-008**: Product requirements must be created from approved discovery, not guessed during bootstrap.
- **MLH-GOV-009**: Documentation must not claim functionality unsupported by code/evidence.
- **MLH-GOV-010**: Existing Git history must not be rewritten destructively without explicit authorization.
